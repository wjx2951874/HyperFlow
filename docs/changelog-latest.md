# v0.6.16.4

1. **短信写入系统收件箱（短信 App 收件箱显示）链路实证并定稿**：
   - 查明根因：写入开关（短信持久化）默认关闭时 milink 原生只写「消息页」可见的
     messageflow，系统短信库无记录；打开开关后流转短信**成功写入 `content://sms/inbox`**
     （`inbox insert direct ok` + `injected via param`，短信铃声正常）。
   - 明确限制：流转协议本身不携带原始号码。发送端设备未 Root/未安装本模块时，
     验证码类短信 address 为服务商名称，小米短信走「验证码聚合卡片」不进收件箱主列表；
     两台设备均 Root 并安装本模块（发送端注入原始号码）可完整写入收件箱。
   - 写入开关说明文案与确认弹窗按此定稿，倒计时 10 秒 → **5 秒**。
2. **流转短信正文清洗「[N条]」聚合标记**：小米验证码聚合前缀（`[2条]...验证码275566`）
   在消息页展示与写入短信库时自动剥离（仅匹配开头，不影响正文内合法内容），flow 表原文保留。
3. **Root 回退写入预埋 `seen`/`type=1`**：root `content insert` 若不显式写 type 可能落
   非收件箱（短信 App 收件箱不显示），预埋 type=1 保证收件箱可见。
4. **消息页搜索框占位靠左对齐**：占位「搜索消息」左距 40dp（对齐短信 App
   `bg_padding_start=39.6dp`），字号 17sp/图标 24dp 保持短信同款。
5. **环境检测收紧注入判定**：废弃 `==LOADED <任意pid>` 假阳性（dex2oat/dalvik 残留），
   仅 `==ML_LOADED`/`==SYS_LOADED` + 探针视为真注入；`runtimeOk` 相应收紧。
6. **本地删除失效修复**：删除本地记录时同步删除 flow 与 localFlow 两处，不再残留。
7. **「重新引导」二次确认**：点击后弹窗明示「可能清除本地数据（短信消息除外）」，
   确认后等待 10 秒进入引导页，期间可取消。
8. **文案清理**：移除「来电在线接听」等失效提示（来电流转仍受系统亮屏限制），
   分身流转说明改为「微信、QQ、钉钉等」。
9. **日志捕获扩容**：App 内日志 tail 800 → **5000** 行，减少流转窗口日志被挤出。
10. **注入版本日志运行时化**：模块注入时打印实际版本号（BuildConfig.VERSION_NAME），
    排查「版本跨度大」显示假象。
